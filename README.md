# Гардероб

Личное приложение для оцифровки гардероба. Вместо съёмки вещи описываешь её словами (или загружаешь скриншот из магазина), приложение находит аккуратные фото, убирает фон и заполняет карточку: название, категория, цвета, материал, сезон, формальность.

## Как это работает

1. Русское описание → `/api/query` (Claude переводит в английский запрос) → `/api/search` → Google Images через Serper (до 20 кадров).
   Claude смотрит на миниатюры и оценивает, совпадают ли цвет и модель и нет ли на кадре человека; лучшие 12 показываются первыми. Если отбор не сработал, поиск всё равно отдаёт результаты.
2. Выбранное фото скачивается через `/api/proxy` (сервер, с защитой от запросов во внутреннюю сеть). Если вещь на человеке, `/api/locate` находит рамку нужной вещи и кадр обрезается по ней.
3. Фон убирается в браузере (`@imgly/background-removal`, модель ~40 МБ грузится один раз).
4. `/api/tag` → Claude определяет вещь и предлагает поля. Всё можно поправить.
5. Вещи хранятся в IndexedDB браузера, на сервере ничего не сохраняется.

Для скриншота, фото или бирки `/api/identify` читает напечатанный текст (бренд, артикул, модель) и отдельно определяет цвет по ткани. Поиск идёт сразу по двум запросам: по артикулу (без служебного префикса: `PC9-36200-0287` → `36200-0287`) и по описанию с цветом; выдача объединяется, а Claude отбирает кадры по описанию. Каждый запрос тратит один кредит Serper, то есть поиск по фото стоит два кредита. Если артикула нет, ищем по описанию. Это не обратный поиск по картинке вроде Google Lens: вещь без видимого текста находится только по описанию.

## Запуск с телефона (без установки чего-либо)

1. Получи ключ Serper: https://serper.dev (первые 2 500 запросов бесплатно, карта не нужна).
2. Получи ключ Anthropic API: https://console.anthropic.com
3. Зайди на https://vercel.com, нажми **Add New → Project**, выбери этот репозиторий.
4. До первого деплоя добавь переменные окружения (Settings → Environment Variables):
   - `ACCESS_CODE` — любой длинный код, он закрывает `/api/*` от чужих;
   - `SERPER_API_KEY`;
   - `ANTHROPIC_API_KEY`.
5. Deploy. Открой адрес на телефоне, при первом поиске введи код доступа.
6. В Safari: «Поделиться → На экран „Домой“». В Chrome: меню → «Установить приложение».

## Локально

```sh
npm install
cp .env.example .env   # впиши ключи
npm run dev
```

- `npm run check` — проверка типов
- `npm test` — тесты (защита прокси, разбор ответов модели, справочники)

## Что важно знать

- Данные живут в браузере конкретного устройства. Очистка данных сайта удалит гардероб, если не включена синхронизация (см. ниже: тогда копия лежит ещё и в хранилище Vercel).
- Приложение запрашивает у браузера постоянное хранилище (`navigator.storage.persist`), чтобы данные не вычищались при нехватке места.
- Без `ACCESS_CODE` на сервере `/api/*` в продакшене отвечает 503.
- Фото из интернета используются только для личного каталога.

## Что надеть и дыры в гардеробе

Оба экрана работают без Claude и без платных ключей: всё считается в браузере по данным карточек (`src/lib/outfits.ts`, `src/lib/gaps.ts`).

**Что надеть.** Прогноз на 7 дней берётся из Open-Meteo (без ключа, Лимассол) и кэшируется на 30 минут; сверху выбирается день. Без сети показывается последний сохранённый прогноз (до 12 часов), а без него погоду можно выбрать вручную. Для сегодняшнего дня показывается текущая температура, для остальных — дневная. Одежда выбирается по ощущаемой температуре середины дня:

| Погода | Второй слой | Куртка |
| --- | --- | --- |
| Жарко, от 27° | нет | нет |
| Тепло, 20–26° | по желанию, если вечером ниже 18° | нет |
| Прохладно, 14–19° | обязателен | только при дожде |
| Холодно, ниже 14° | обязателен | обязательна |

Второй слой берётся только из категорий: пиджак/жакет, худи, свитер/джемпер, водолазка, кардиган. Куртки и пальто сюда не попадают, они отдельным слоем. Шорты предлагаются только в жару и тепло, вещи с неподходящим сезоном не берутся (если выбора нет, образ собирается с пометкой).

Цвета: нейтральные (чёрный, белый, серый, бежевый, коричневый, тёмно-синий) сочетаются со всем; цветных не больше двух, из них один яркий, спорные пары (красный с зелёным, оранжевым; оранжевый с розовым, фиолетовым) не допускаются, принт носится без других цветных. Формальность в образе не должна расходиться больше чем на две ступени (спорт и деловой стиль вместе не пойдут).

Показывается 3–4 разных образа по цвету и модели: образы, отличающиеся только курткой или обувью, считаются одним. Вещи, которые давно не надевались, получают небольшой плюс. «Другие варианты» перемешивает подбор, «Надену это» (только для сегодняшнего дня) записывает вещи в журнал.

**Журнал.** Календарь носки: выбираешь день (будущие недоступны), отмечаешь вещи, обувь и сумки или рюкзаки, которые были на тебе, и можно поправить любой прошлый день. Запись дня меняет счётчик «надето N раз» и дату последней носки у вещей; журнал и вещи пишутся одной транзакцией IndexedDB, поэтому не расходятся. «Надела сегодня» в карточке вещи тоже пишет в журнал (дважды за день не засчитывается).

**Статистика.** Отдельно одежда, обувь, сумки и рюкзаки: сколько раз надето за 30 дней, 90 дней или за всё время, что давно не надевалось и что не надевалось ни разу. Периоды 30 и 90 дней считаются по датам из журнала; «Всё время» берёт счётчик вещи, в нём сохранились и отметки, сделанные до журнала.

**Дыры.** Для каждого из четырёх периодов считается, сколько разных образов можно собрать (до 12), и каких слоёв не хватает. Отдельно находятся вещи, с которыми нельзя собрать ни одного образа, и предлагается докупить нейтральные вещи, которые дадут больше всего новых образов.

Список редактируется. «Мой список» — то, что хочешь докупить сама: категория, цвет (или любой), название, заметка. Для каждой записи показано, сколько новых образов она даст с твоим гардеробом (сумки и рюкзаки в образы не входят). Совет можно добавить в список одной кнопкой или скрыть («Не нужно»: категория больше не предлагается, вернуть можно внизу). «Купила» открывает добавление вещи с названием из списка и после сохранения убирает запись. Список хранится в IndexedDB браузера, как и гардероб, и синхронизируется между устройствами.

**Скриншоты в списке.** К записи можно добавить до 6 скриншотов: кнопкой, из галереи или вставкой из буфера (Ctrl/⌘ + V). Несколько скриншотов складываются в мозаику-коллаж (1 — как есть, 2–6 — плотная сетка с одной крупной картинкой), поэтому «образ, который хочу собрать» выглядит как мудборд, а не как россыпь картинок. Для такой записи категория и название необязательны: без категории подсчёт «сколько образов даст» не показывается. Скриншоты сжимаются до 900 px по длинной стороне.

**Образы в «Что надеть» — коллажи.** Вещи образа лежат на одной доске 4:5 как flatlay: верх над низом, второй слой выглядывает слева, куртка справа, обувь внизу, у вещей небольшой наклон и мягкая тень. Расположение считает `src/lib/collage.ts` (набор ролей → положение, масштаб подгоняется так, чтобы набор был по центру и занимал доску). У вырезанных из фона вещей тень, у фото с белым фоном фон сливается с доской (`mix-blend-mode: multiply`). Под коллажем подпись: какие именно вещи.

## Бренд

У вещи есть поле «Бренд». Оно заполняется само: с бирки или скриншота его читает `/api/identify`, а при поиске словами (например «рубашка Zara») бренд берёт `/api/tag`. Подставляется только в пустое поле, вручную можно поправить. Вещи, добавленные раньше, открываются с пустым брендом.

## Синхронизация между устройствами

Синхронизируются вещи (с фото), журнал носки, список желаемого (со скриншотами) и скрытые подсказки. Данные лежат в **закрытом** хранилище Vercel Blob: состояние одним файлом (`state/wardrobe.json`), каждое фото отдельно (`photos/<ключ>`). Пока синхронизация выключена, на сервер не уходит ничего.

**Настройка (один раз):**
1. В Vercel: проект → Storage → Create → Blob → при создании выбери доступ **Private**, подключи к проекту. Vercel сам добавит переменную `BLOB_READ_WRITE_TOKEN`.
2. Сделай redeploy проекта.
3. В приложении нажми круглую кнопку со стрелками справа вверху → «Включить синхронизацию». На втором устройстве — то же самое (и тот же код доступа).

**Как устроено:**
- Приложение отправляет своё состояние на `/api/sync`, сервер сливает его с хранимым и возвращает общее. Запись условная (по `etag`), поэтому два устройства, синхронизирующиеся одновременно, не затирают друг друга: проигравший читает заново и сливает ещё раз.
- Слияние: у каждой вещи и желания есть время правки, побеждает более поздняя. Отметки «надела» хранятся отдельно для каждой пары «день + вещь», поэтому носка, записанная на телефоне и на компьютере в разные дни, складывается, а не заменяется. Счётчики носки после обмена пересчитываются из журнала.
- Удаления помнятся («надгробия»): вещь, удалённая на одном устройстве, не вернётся со старой копии другого.
- Фото неизменяемы: при замене фото вещь получает новый ключ. Фото загружаются и скачиваются только те, которых не хватает.
- Отправка идёт через 3 секунды после правки, при возвращении в приложение и при появлении сети.

**Ограничения:**
- «Какая правка новее» решают часы устройств; если на одном из них время сильно сбито, его правки могут выиграть или проиграть неправильно.
- Если при замене фото старое остаётся в хранилище, оно не удаляется (мусор занимает место, но ничему не мешает).
- Фото одного размера не больше 3 МБ, всё состояние не больше 4 МБ; это с большим запасом для личного гардероба, но на несколько тысяч вещей и 200 тысяч отметок рассчитывать не стоит.
- Без подключённого хранилища кнопка покажет «Хранилище не подключено», остальное приложение работает как раньше.
- Для разработки без Vercel: `SYNC_DIR=/tmp/wardrobe-sync npm run dev` пишет в папку вместо Blob.
